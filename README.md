# 差速驱动机器人里程计标定

给定机器人在已知路径上行驶采集的**编码器增量序列**与对应的**真实位姿序列**，
用最小二乘标定差速驱动的系统性参数（左右轮有效半径比、有效轮距），
鲁棒剔除打滑/碰撞异常帧，并用训练/验证划分检测过拟合，
最终生成一个单一静态 HTML 报告对比校正前后的轨迹与误差。

仅使用 Go 标准库；前端为原生 HTML/CSS/JavaScript + Canvas，无任何第三方依赖。

## 运行

```bash
# 使用内置合成演示数据（含已知偏差与异常帧）
go run . -out report.html

# 使用真实采集数据
go run . -input data.json -out report.html -train 0.6

# 测试
go test ./...
```

输入 JSON 格式：

```json
{
  "nominal": {"ticksPerRev": 1024, "wheelRadius": 0.05, "wheelBase": 0.30},
  "frames": [
    {"ticksL": 0, "ticksR": 0, "x": 0, "y": 0, "theta": 0},
    {"ticksL": 163.2, "ticksR": 165.1, "x": 0.05, "y": 0.001, "theta": 0.002}
  ]
}
```

`ticksL/ticksR` 为相对上一帧的编码器增量；`x/y/theta` 为该帧真实位姿。
程序退出码：0 标定有效；2 标定不可靠（过拟合/数据不足）；1 输入错误。

## 一、标定模型

差速驱动运动学（帧 i 的编码器增量 nL、nR，单位 tick）：

```
ΔsL = sL·nL        ΔsR = sR·nR          （sL/sR：每 tick 有效位移）
Δd  = (ΔsL + ΔsR)/2                     （弧长）
Δθ  = (ΔsR − ΔsL)/B                     （B：有效轮距）
```

位姿积分采用**精确圆弧模型**（等曲率假设）：

```
chord = Δd · sin(Δθ/2)/(Δθ/2)           （Δθ→0 时取极限 Δd）
x' = x + chord·cos(θ + Δθ/2)
y' = y + chord·sin(θ + Δθ/2)
θ' = θ + Δθ
```

由真值序列反推每帧真实增量：Δθ 取朝向差（归一化到 ±π），
平移取弦长并做**弧长修正** `arc = chord·(Δθ/2)/sin(Δθ/2)`，
与积分的圆弧模型严格互逆——这一点在高曲率转弯帧上至关重要
（中点积分的弦长误差达 6%/rad² 量级，会把正常转弯帧污染成"异常帧"）。

### 最小二乘 formulation

把模型按帧写成两个独立的线性方程：

```
平移: arc_i = (sR/2)·nR_i + (sL/2)·nL_i
旋转: Δθ_i  = (sR/B)·nR_i + (−sL/B)·nL_i
```

各自是二元线性最小二乘，用正规方程闭式求解（2×2，克拉默法则）。
由四个系数还原物理参数：`sR, sL, B = sR/c_R ≈ sL/c_L`（两路估计取平均，
不一致超过 50% 判定模型与数据不符）。输出：

- **轮半径比** rR/rL = sR/sL（修正左右轮径差异）
- **有效轮距** B（修正轮距误差）
- 左右轮各自的每 tick 有效位移 sL、sR

### 可辨识性（激励充分性）

直线行驶时 nR≈nL，平移方程两列共线，左右轮尺度不可分离；
无转弯时旋转方程无激励，轮距不可辨识。求解前检查设计矩阵列相关系数，
|corr| > 0.995 判定**激励不足**并报"数据不足"，而不是输出无意义的参数。

## 二、异常帧剔除

打滑/碰撞帧的本质：**编码器增量与真值增量脱节**，运动学模型无法解释。
采用迭代鲁棒剔除（类似 sigma-clipping）：

1. 在当前保留帧上最小二乘拟合；
2. 计算每帧归一化残差（平移/旋转两通道取大者）：

   ```
   u_i = max( |res_arc| / (σ_arc + κ·|arc_i|),
              |res_rot| / (σ_rot + κ·|Δθ_i|) )
   ```

   - σ 用 **MAD（中位绝对偏差）** 估计的鲁棒噪声尺度——少数巨大异常值
     不会撑大门限导致漏检；
   - 相对项 κ·|运动量|（κ=2%）吸收参数残差在大运动量帧上的放大效应——
     **正常高曲率转弯帧**的残差随转弯角同步放大，相对项使其不被误剔；
     而打滑（读数暴涨数倍）/碰撞堵转（读数趋零而真值在动）帧的残差
     是门限的几十到上千倍，必然被捕获；
3. 剔除 u_i > 3.5 的帧并重新拟合，直到剔除集收敛（剔除集每轮基于
   全部帧重算，允许被误剔的帧在拟合改善后**回入**，避免累积误剔）；
4. 剔除比例超过 20% 判定数据整体异常，拒绝输出参数。

## 三、过拟合检测

把帧序列按时间**连续切分**为训练段（前 60%，可用 `-train` 调整）与验证段。
连续切分而非随机抽样：验证段是一条完整的未知轨迹，能真实检验泛化能力。

- 训练段：鲁棒标定得到参数；
- 验证段：从该段真值起点出发，仅用编码器数据分别按**标称参数**与
  **标定参数**积分，对比终点误差与 RMSE（验证段的打滑帧用训练好的
  门限剔除，避免污染评估）。

判定标定**不可靠**（任一命中）：

1. 训练段拟合失败（激励不足、异常帧过多、非物理参数）；
2. 验证段终点误差或 RMSE 升高超过 10%（过拟合的典型信号）；
3. 验证段改善不足 20%（参数没有泛化价值）；
4. 训练段本身无明显改善（系统误差本来就不显著，标定无意义）。

失败时程序明确报告原因并以退出码 2 结束，**不会输出看似合理但不可靠的参数**。

## 四、HTML 报告

单一静态文件，数据与逻辑全部内嵌，浏览器直接打开，无需任何服务与依赖：

- 标定结论徽标（有效/不可靠 + 原因列表）；
- 参数对比表（标称 vs 标定，含偏差百分比）；
- 误差指标表（全序列 + 验证段，校正前后对比与改善率）；
- X-Y 轨迹图：真值 / 校正前 / 校正后轨迹，异常帧橙色高亮，
  训练/验证分界标记；
- 逐帧位置误差曲线（校正前 vs 校正后，含训练/验证分界线）；
- 被剔除异常帧下标列表。

## 五、测试覆盖

`go test ./...`：

| 测试 | 覆盖点 |
|---|---|
| `TestLin2` | 最小二乘求解器精度与共线病态检测 |
| `TestCalibrateConverges` | 已知轮径比 +2% / 轮距 −4% 偏差下，标定收敛到真值 0.5%/1% 以内 |
| `TestOutlierRejection` | 8 个打滑/碰撞帧全部被剔除；正常高曲率转弯帧零误伤；剔除后参数仍收敛 |
| `TestValidationPassesOnGoodData` | 良好数据验证通过且验证段误差显著下降 |
| `TestOverfitDetected` | 训练段纯直行（无旋转激励）时正确报告标定失败/数据不足 |
| `TestPureStraightDetected` | 全程直行数据被拒绝 |
| `TestTooFewFrames` | 帧数不足报错 |
| `TestWrapAngle` / `TestGTIncrementsArcCorrection` | 角度归一化与弦长→弧长修正 |

## 文件结构

```
main.go       CLI 入口、演示数据生成、报告输出
model.go      位姿/帧类型、运动学积分（精确圆弧模型）、轨迹误差评估
calibrate.go  最小二乘标定 + MAD 迭代鲁棒异常帧剔除
validate.go   训练/验证切分与过拟合判定
synth.go      合成数据生成（demo 与测试共用）
report.go     报告数据汇总
template.go   单文件 HTML 模板（原生 JS + Canvas）
main_test.go  自动化测试
```
