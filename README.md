# meter — 差速驱动机器人里程计标定

仅使用 Go 标准库实现的差速驱动里程计系统标定工具：从「编码器读数 + 位姿真值」
序列中估计系统性误差修正系数，鲁棒剔除打滑/碰撞异常帧，并用留出验证集检测过拟合。
最终产出一个**单一静态 HTML 报告**（数据与逻辑全部内嵌，原生 HTML/CSS/JS + Canvas，
无任何第三方库、无需启动服务）。

## 快速开始

```bash
go run . -demo -out report.html        # 内置仿真数据演示（含打滑帧）
go run . -input log.json -out report.html   # 标定真实数据
go test ./...                          # 运行自动化测试
```

标定结果不可信（过拟合或数据不足）时程序以退出码 2 结束，可直接接入 CI。

### 输入格式（JSON）

```json
{
  "ticks_per_rev": 4096,
  "wheel_radius": 0.05,
  "wheel_base": 0.32,
  "frames": [
    {"tl": 0,  "tr": 0,  "x": 0.0, "y": 0.0, "theta": 0.0},
    {"tl": 12, "tr": 13, "x": 0.001, "y": 0.0, "theta": 0.0001}
  ]
}
```

`tl`/`tr` 为相邻两帧间的左右轮编码器 tick 增量；`x/y/theta` 为该帧的位姿真值
（如动捕系统输出）。`-dump log.json` 可查看 demo 生成的完整样例。

## 一、标定模型

### 运动学模型

编码器增量 → 位姿增量的映射由三个系统性修正系数参数化（1.0 表示与标称值一致）：

```
c  = 2π·r / N                     （标称每 tick 里程，r 轮半径，N 每转线数）
dL = KL · c · nL                  （左轮实际弧长）
dR = KR · c · nR                  （右轮实际弧长）
ds = (dL + dR) / 2                （平移增量）
dθ = (dR − dL) / (KB · b)         （转向增量，b 标称轮距）
```

- **KL, KR**：吸收左右轮有效半径差异（轮径误差、胎压/磨损不对称），即可修正的
  轮径系统性偏差；
- **KB**：吸收轮距有效值误差（轮距测量误差、转弯时轮胎接地点偏移）。

位姿积分采用中点（圆弧）积分：`θ += dθ`，`x += ds·cos(θ − dθ/2)` 等。
真值侧增量由相邻真值位姿反解：`dθ` 取角度差（包裹到 [−π, π]），`ds` 取位移模长
并按航向投影定号（兼容倒车）。

### 最小二乘拟合

将模型对真值增量做线性最小二乘，全部为闭式解，无需任何矩阵库：

1. **平移**：`dsᵢ = a·nLᵢ + b·nRᵢ`，2×2 正规方程解出 `a = c·KL/2`、`b = c·KR/2`。
   当数据近似纯直线（`nL ≈ nR`，正规方程秩亏）时退化为单一共用尺度因子，
   避免病态解——此时 KL、KR 单独不可辨识，只有其调和组合可辨识。
2. **旋转**：固定 KL、KR 后，`dθᵢ = (1/KB)·uᵢ`，`uᵢ = (KR·nRᵢ − KL·nLᵢ)·c/b`，
   一维最小二乘解出 `KB`。若总转角激励不足（Σ|u| ≈ 0），KB 保持 1.0 并明确
   报告「不可辨识」，不输出垃圾数值。

可修正的系统误差（恒定轮径比、轮距偏差）被系数吸收；逐帧的编码器量化噪声、
地面微观不平等**随机噪声**无法被常系数解释，留在残差中——二者由此区分。

## 二、异常帧剔除策略

打滑/碰撞瞬间，编码器读数与真值脱节，**没有任何一组 (KL, KR, KB) 能解释该帧**，
其残差对参数选择鲁棒地大。剔除流程（`calib/outlier.go`）：

1. 用当前内点集做最小二乘拟合；
2. 计算逐帧残差 `rᵢ = hypot(Δds, b·Δdθ)`（模型预测增量 vs 真值增量）；
3. 用 **MAD（中位数绝对偏差）** 估计鲁棒噪声尺度 `σ = 1.4826·MAD`，
   阈值 `T = median + 8σ`，并设绝对下限 0.02 m 防止超净数据被误刮；
   MAD 本身不被离群值污染，因此阈值稳定；
4. 剔除 `rᵢ > T` 的帧，重新拟合，迭代至收敛（上限 6 轮）；
5. **硬性上限**：剔除比例不得超过总帧数 25%（超出时只保留残差最大的若干帧），
   防止把整段正常数据误判掉。

**为什么不会误伤正常高曲率转弯**：运动学模型对转弯是*精确*的——急转弯只是
一个较大的 dθ，模型能从编码器读数中同样复现它，因此正常转弯帧的残差仍处于
噪声水平。阈值作用在**残差**上而非曲率上，只有模型无法解释的跳变（打滑/碰撞）
才会越限。测试 `TestHighCurvatureFramesSurvive`（纯急转/原地旋转数据零误剔）与
`TestOutlierRejection`（注入 10 个打滑帧全部捕获、零误报、参数仍收敛）覆盖此行为。

## 三、过拟合检测（留出验证）

标定流程（`calib/calibrate.go`）：

1. 将日志按时间切成 5 个连续段，**偶数段训练、奇数段验证**（交错分块保证两段
   都覆盖多种运动形态，且块内连续可评估累积漂移）；
2. 仅在训练段内点上拟合参数；
3. **数据充分性检查**：训练帧数 ≥ 50、训练里程 ≥ 2 m、总转角 ≥ 2 rad
   （否则 KB 不可辨识）；任一不满足 → 判定 `INSUFFICIENT DATA`；
4. **稳定性检查**：训练集前后两半分别拟合，参数漂移 > 0.03 时给出警告；
5. **验证集裁决**：在验证段上分别从段起点真值做航位推算，比较段末位姿误差
   （位置误差 + 轮距×航向误差）。要求校正后 RMS 误差相对校正前下降 ≥ 10%，
   否则判定 `OVERFIT / UNRELIABLE` 并**拒绝输出可信结论**——典型情形是标称
   参数本来就正确、拟合的只是噪声，验证集误差反而上升；
6. 参数物理合理性：任一系数偏离 1.0 超过 ±50% 视为数据/建模问题，判失败。

## 四、HTML 报告

`report/` 将结果渲染为单一静态 HTML 文件，浏览器直接打开即可：

- 轨迹对比画布：真值（黑）、校正前（红）、校正后（蓝），可勾选切换图层；
- **橙色圈叉标记**高亮每个被剔除的异常帧（画在其真值位置）；
- 逐帧残差条形图：内点蓝条、异常帧橙条、虚线为 MAD 鲁棒阈值；
- 参数表（含前后半段稳定性对照）、训练/验证误差对比表、判定依据列表。

## 项目结构

```
main.go            CLI 入口（-demo / -input / -dump / -out）
calib/             标定核心库（纯标准库）
  types.go         数据结构与配置
  model.go         运动学模型与航位推算
  fit.go           闭式最小二乘拟合
  outlier.go       MAD 鲁棒异常帧剔除
  validate.go      段切分与误差评估
  calibrate.go     标定主管线与过拟合裁决
  sim.go           合成数据生成器（测试与 demo 共用）
  calibrate_test.go
report/            单文件 HTML 报告渲染（原生 JS + Canvas）
```
